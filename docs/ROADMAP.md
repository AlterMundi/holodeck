# Holodeck MVP roadmap

Human-authorized active native goal: work through a shared, testable MVP.
Updated 2026-11-17. This roadmap is acceptance coverage, not a completion claim.

| Outcome | Implemented and checked | Still required |
| --- | --- | --- |
| [Native situated participation #1](https://github.com/AlterMundi/holodeck/issues/1) | Exact original + immutable situation adapter; current pair/binding lookup; durable uncertain-intent recovery; direct native world port; controlled tests | Other pairs' receiving routes and an actual fresh human situated input -> native uptake -> observed world action -> result |
| [Playable shared creation #2](https://github.com/AlterMundi/holodeck/issues/2) | MML world/presence; bridge; preview/accept/cancel/undo; shared authority; persisted run/commands; keyboard and emulated touch | Protected multi-actor acceptance, reconnect through the hosted route, real companion collaboration |
| [Quality and device trial #3](https://github.com/AlterMundi/holodeck/issues/3) | Original low-poly island; bounded lighting; desktop/touch HUD; real browser movement/creation checks | Human play and physical phone/tablet acceptance; further quality based on their use |
| [Durable sharing #4](https://github.com/AlterMundi/holodeck/issues/4) | Existing Home package/auth boundary; bounded state; independent protected HTTPS release/audience; bounded GLB content export | Authenticated shared trial; recovery qualification; creation/review/publication cycle remains distinct from service deployment |

The MVP includes a walkable 3D world. QR scanning and augmented physical mapping
remain candidate creations. Avatar/VR refinement is not a prerequisite for the
initial explicit turn-based Conversation mode. No canned companion can satisfy
native acceptance. Keep the goal active until its actual required work is done.

See [plan](plan.md), [current evidence](STATUS.md), [native contract](native-integration.md),
[visual checks](visual-play.md) and the owning deployment record when available.
